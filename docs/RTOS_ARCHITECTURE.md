# ESP32 FreeRTOS 多任务架构 (WiFi 照片版)

## 概述

项目使用 FreeRTOS 多任务系统，充分利用 ESP32 双核优势。

## 任务分配

```
┌─────────────────────────────────────────┐
│         FreeRTOS 任务调度器              │
├─────────────────────────────────────────┤
│  核心0 (PRO_CPU)     │  核心1 (APP_CPU) │
├─────────────────────────────────────────┤
│  监控任务            │  WiFi 任务        │
│  优先级: 2           │  优先级: 3        │
│  系统监控和状态       │  HTTP 服务器      │
├─────────────────────────────────────────┤
│  显示任务            │  应用任务         │
│  优先级: 2           │  优先级: 1        │
│  LVGL 屏幕刷新       │  业务逻辑         │
├─────────────────────────────────────────┤
│  Idle任务            │  Idle任务         │
│  优先级: 0           │  优先级: 0        │
└─────────────────────────────────────────┘
```

## 任务详情

| 任务名           | 核心    | 优先级  | 功能               | 堆栈 |
| ---------------- | ------- | ------- | ------------------ | ---- |
| **WiFi_Task**    | 核心1   | 3(最高) | HTTP服务器接收照片 | 8KB  |
| **Monitor_Task** | 核心0   | 2       | 状态监控、串口输出 | 4KB  |
| **Display_Task** | 核心0   | 2       | LVGL 屏幕刷新      | 4KB  |
| **App_Task**     | 核心1   | 1       | 应用业务逻辑       | 4KB  |
| **Idle**         | 核心0,1 | 0(最低) | 空闲回收           | 内置 |

## 任务优先级

```
优先级 3  ┌──────────────────────┐
(最高)   │  WiFi_Task           │  HTTP 请求处理，保证不丢数据
         └──────────────────────┘

优先级 2  ┌──────────────────────┐
         │  Monitor_Task        │  状态显示 + LVGL刷新
         │  Display_Task        │
         └──────────────────────┘

优先级 1  ┌──────────────────────┐
         │  App_Task            │  应用业务，低优先级
         └──────────────────────┘

优先级 0  ┌──────────────────────┐
(最低)   │  Idle_Task           │  空闲回收
         └──────────────────────┘
```

## 通信机制

### 互斥锁

```cpp
// WiFi 互斥锁 - 保护 WiFi 状态快照
SemaphoreHandle_t wifiMutex = NULL;

// 使用方式:
if (xSemaphoreTake(wifiMutex, pdMS_TO_TICKS(5)) == pdTRUE) {
    gWifiStatusSnapshot = wifiStatus;  // 写入
    xSemaphoreGive(wifiMutex);
}
```

### 共享快照

WiFi 任务（核心1）写入状态快照 → Display/Monitor 任务（核心0）读取。

- 单写多读模式
- 无需队列，减少内存开销

## 任务执行流程

### WiFi_Task (优先级3)

```
loop:
  等待10ms ──→ 处理HTTP请求 ──→ 接收图像数据
                                    ↓
                              写入SPIFFS
                                    ↓
                              更新状态快照
                                    ↓
                               回到loop
```

### Monitor_Task (优先级2)

```
loop:
  等待500ms ──→ 读取状态快照
                    ↓
          状态改变? 打印状态变更信息
                    ↓
          每5秒? 显示系统状态和任务信息
                    ↓
               回到loop
```

### Display_Task (优先级2)

```
loop:
  读取状态快照
       ↓
  检测 imageReady?
       ├─ Yes: 从 SPIFFS 加载新图像 → LVGL 刷新
       └─ No:  继续
       ↓
  每500ms 更新状态显示
       ↓
  displayProcess(5ms) 驱动 LVGL
       ↓
  vTaskDelay(5ms)
```

## 系统启动顺序

```
1. Serial 初始化 (115200)
   ↓
2. 板级引脚初始化 (boardPinInit)
   ↓
3. WiFi 图像管理器初始化
   ├─ WiFi.mode(WIFI_AP)
   ├─ WiFi.softAP("ESP32_Photo", "12345678")
   └─ HTTP Server 启动 (端口 80)
   ↓
4. FreeRTOS 系统初始化
   ├─ 创建互斥锁 (wifiMutex, sysMutex)
   ├─ 创建 WiFi_Task (核心1, 优先级3)
   ├─ 创建 Monitor_Task (核心0, 优先级2)
   ├─ 创建 Display_Task (核心0, 优先级2)
   └─ 创建 App_Task (核心1, 优先级1)
   ↓
5. loop() → Idle 任务
   ↓
6. 各任务并发运行
```
